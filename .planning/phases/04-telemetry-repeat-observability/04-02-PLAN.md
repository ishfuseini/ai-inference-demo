<objective>
Deliver the repeat/cache scenario slice: a deterministic two-run sequence that observes a repeat of the same prompt/strategy and reports provider cache metadata only when the provider actually returned it, falling back to observed first-vs-second latency and cost otherwise.

**As a** forward-deployed engineer, **I want to** trigger a repeat of my last prompt and see honest cache/repeat evidence, **so that** I can demonstrate cache-hit detection versus plain latency/cost deltas in the demo.

Purpose: Add the `run_repeat_scenario` two-run orchestration (mirroring `run_fallback_scenario`) and the `Repeat` UI action, with cache-honesty enforced by `tests/test_repeat.py`.
Output: `RepeatObservation`, `run_repeat_scenario`, `_run_repeat_inference`, the Repeat switch, and the repeat/cache test file.
</objective>
